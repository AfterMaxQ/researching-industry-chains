# 产业链来源检索与解析

## 适用范围

用于按正式主题检索独立来源，把网页、PDF、图片和表格中的产业链节点及企业归属转换为九字段数据。运行时必须具备搜索、浏览器、截图或 PDF 渲染、视觉读图和 industry-chain CLI 能力。缺少其中任一关键能力时，不得用正文猜图；领取主题后发现能力不可用，提交失败状态。

## 启动与租约

所有 Runner 命令都显式传入 runner-id。

新建或继续批次：

~~~text
industry-chain runner create --name <任务名称> --config <topic_identity.yaml路径>
industry-chain runner status --runner-id <runner_id>
industry-chain topic claim-next --runner-id <runner_id>
~~~

补跑失败主题或重开终态主题：

~~~text
industry-chain topic claim --runner-id <runner_id> --node-id <node_id>
industry-chain topic claim --runner-id <runner_id> --node-id <node_id> --reopen
~~~

保存领取响应中的 claim_token 和 lease_expires_at。主题处于 in_progress 时，写入、修改、替换、删除、续租、完成和失败都携带当前有效令牌。长时间检索至少每 20 分钟续租一次：

~~~text
industry-chain topic renew --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token>
~~~

### SubAgent 派发模板（启用 SubAgent 时使用）

把以下短模板和实际参数发送给研究 Agent。并行任务只填写不重叠的 node_id 范围，不预设来源、节点或企业。

~~~text
你负责 Runner {{runner_id}} 的 node_id {{node_id 或范围}}。先读取 researching-industry-chains/SKILL.md，领取或确认主题并保存有效 claim_token。

对候选来源先做产业链证据门禁；通过后扫描来源全文和全部分页，建立来源图表清单、节点清单和企业清单。先看整图，只有内容读不清时才局部裁切或放大。

先完整还原来源树，再把企业挂到直接证据支持的节点。不能凭常识补节点或企业，不能把父节点企业继承给子节点。写入前确认所有可读节点都有路径行、所有企业证据组都已挂载或明确无法归属。

每个完整来源一次性通过 CLI 写入九字段 records；所有写入和终态操作携带有效 claim_token。搜索饱和后提交 completed、no_qualified_source 或 fail，并汇报 node_id、正式主题、终态、来源组数、行数、来源 URL 和交付 XLSX 路径。
~~~

## 单个主题的执行流程

### 1. 确认主题身份

领取结果中的正式主题、path 和 aliases 是本次任务的身份依据。path 只用于理解目录位置，不是产业链节点。搜索词覆盖正式主题、批准别名、相关表达，以及产业链、产业图谱、全景图、企业布局、竞争格局、研究报告等限定词。

来源范围比正式主题宽或窄时可以保留，但首行备注写明范围变化和具体差异。明显相邻但不是同一产业链的来源排除。图题、章节和正文指向同一产品或技术路线时按精确匹配处理；只有明确扩大或缩小产业范围时才标记范围变化。优先采用 2024 年及以后来源；较早来源或发布日期未识别时，在来源首行备注说明。

### 2. 来源证据门禁

一个来源只有同时满足以下条件才形成来源组：

1. 图、表或正文明确表达上游/中游/下游、供应商—制造商—应用方、原材料—生产—应用等产业链关系；
2. 至少一组企业能通过来源内部证据直接对应某个节点。

标题写“产业链”本身不够。以下内容即使有框、箭头或分类，也不能单独作为产业链证据：

- 技术路线、系统架构、工艺流程、业务流程和工作原理；
- 产品结构、零部件清单和应用场景图；
- 展商目录、企业名单、上市公司名单和区域热力图；
- 只有公司名称，没有公司与具体节点关系的内容。

未通过门禁不得生成节点、企业记录或调用 dataset insert。来源可以不完整，但通过门禁后，图中没有企业的其他节点仍保留。来源优先顺序为政府机构、研究院、证券研报、咨询机构、行业协会、权威数据平台和企业白皮书。媒体、转载平台、文件站和主体不明来源只要证据合格也可保留，但必须准确标注转载关系：原始发布写原始主体；转载或托管写发布平台（原始主体）；只能识别发布平台时写发布平台（原始主体未明）。

### 3. 扫描完整来源

同一网页、报告或 PDF 独立形成一个来源组。同一底层文档的转载或托管版本只保留一组；网页分页属于同一来源，不因 URL 不同拆组。

先检查全文、目录、图号、图题、分页和正文引用，建立内存中的来源图表清单：

~~~text
图表/页码 | 类型 | 是否有产业链节点 | 是否有企业关系 | 是否已读取
~~~

类型至少区分：主产业链图、企业图/表、正文结构、数据图和非链图。只有通过门禁的内容进入深度解析；流程图、架构图和无链条语义的企业目录标为非链图并排除。

先查看完整页面或完整图。只有节点、企业名或连接关系无法可靠读取时，才对对应区域按需裁切或放大；已经清晰的区域不重复处理。OCR、正文抓取、搜索摘要或图片下载成功不能替代视觉检查。

网页有分页时确认总页数并扫描全部分页。复合页面中的每个图题、图表和企业表分别判断，但不要求对每个区域机械重复截图。继续扫描，直到不再出现新的产业链节点或可归属企业。发现但未能可靠读取的内容不能当作已完成；来源仍合格时只交付可确认内容，并在首行备注说明未解析范围。

### 4. 还原节点和企业

先按原图中的框、标题、连接线、分组、缩进和阅读方向还原产业链树，再投影为数据行。每一行表示一条从根节点到终点的完整路径，以及直接归属于该终点的企业集合。不得先凭行业知识建立标准产业链，再把图片文字套入预设结构。

图表优先于正文。正文只有明确表达产业链层级或企业与节点关系时，才能补充图表未展示的内容。普通产品介绍、业务描述和顺带提及的名词不能生成节点。

企业归属按以下优先级判断：产业链图明确位置、企业图或企业表分组、正文明确介绍。企业列表必须能对应已有节点；正文必须明确表达企业生产、提供或布局该节点产品或服务。相关企业、代表公司、行业参与者等无节点关系名单不得挂载。

在内存中同时维护两份清单：

~~~text
节点清单：图表/页码 -> 完整节点路径 -> 对应数据行
企业清单：图表/页码 -> 企业组 -> 直接对应节点 -> 已挂载或无法归属
~~~

先完整读取已接受来源，再判断主题范围。接受较宽来源时保留来源中可读的产业链节点和直接企业证据，并在备注说明范围变化；不能保留兄弟节点，却只删除命中主题关键词的企业。只有上游任务明确指定叶子子集时，才执行叶子级过滤。

节点名称、层级和顺序保持原文原图，不标准化、不润色、不补全。一个框表达组合节点时原样保留；多个并列节点拆成多条路径；省略号和装饰文字不生成节点。分类 1 至分类 4 必须连续，超过四级时从分类 4 起按原始顺序合并。

企业只写在直接证据支持的节点行。证据只到父节点时只挂父节点，不向子节点继承；企业无法确认归属时公司留空，必要时在来源首行备注说明。同一路径的企业合并到同一行，完全重复名称删除，按来源出现顺序用顿号连接。优先使用来源内部确认的企业全称；只能确认品牌名或简称时保留原样，不用外部知识扩展。证据冲突时优先级高的证据优先，无法消解时不强行挂载，并在来源首行说明。

### 5. 写入来源组

来源完整解析后，在内存中整理 records，不创建中间 JSON、证据目录、截图、PDF、OCR 文件或日志。固定载荷如下：

~~~json
{
  "records": [
    {
      "主题": "正式主题",
      "信源主体": "发布主体",
      "分类1": "上游",
      "分类2": "节点",
      "分类3": "",
      "分类4": "",
      "公司": "甲公司、乙公司",
      "信源URL": "https://example.com/report",
      "备注": "仅来源组第一行可填写"
    }
  ]
}
~~~

九个字段全部是字符串。主题、信源主体、分类 1 和信源 URL 不能为空；分类不能断层；组内主题、信源主体和 URL 必须一致；只有第一行填写备注；来源组至少一行公司非空；信源 URL 必须是合法 HTTP(S) 地址。来源组内按原图或原文阅读顺序排列。

写入前必须同时通过两项覆盖检查：

- 每个可读产业链节点都有对应路径行；
- 每个可读企业证据组都已挂载到直接支持的节点，或已明确判断为无法归属。

任一项未完成，不得写入或提交来源终态。完整来源一次性写入：

~~~powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$env:PYTHONIOENCODING = 'utf-8'
$payload = @'
{"records":[
  {
    "主题":"正式主题",
    "信源主体":"发布主体",
    "分类1":"上游",
    "分类2":"节点",
    "分类3":"",
    "分类4":"",
    "公司":"企业名称",
    "信源URL":"https://example.com/report",
    "备注":""
  }
]}
'@
$payload | industry-chain dataset insert --runner-id <runner_id> --scope source_group --parent-id <node_id> --claim-token <claim_token> --input -
~~~

PowerShell 向原生命令传递中文时必须显式使用 UTF-8。成功响应返回 source_group_id 和 row_id。需要纠正时先用 dataset get 查看，再用 dataset patch、dataset replace 或 dataset remove 精确修改；不要通过逐行提交绕过来源级校验。XLSX 是交付投影，修改以 Runner JSON 为准。

### 6. 搜索饱和和主题终态

每写入一个来源后继续搜索，不设置固定来源数量。完整轮次覆盖正式主题、批准别名和相关表达，并组合产业链、产业图谱、全景图、研究报告、企业布局和竞争格局等限定词。第二轮改变查询组合或来源入口，并对 URL 做底层文档去重。连续两轮没有新增独立合格来源后，才算搜索饱和。

已有来源组时提交完成：

~~~text
industry-chain topic finish --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token> --outcome completed
~~~

搜索饱和且没有合格来源时提交：

~~~text
industry-chain topic finish --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token> --outcome no_qualified_source
~~~

浏览器、网络、视觉能力或运行环境出现系统性异常时提交失败：

~~~text
industry-chain topic fail --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token> --code <错误代码> --message <简短说明>
~~~

主题终态后立即汇报 node_id、正式主题、终态、来源组数量、写入行数、来源 URL 和交付 XLSX 路径；失败时补充原因。自动批次只领取 pending 主题；失败主题由明确补跑重新领取。

## 快速检查

- 来源同时有产业链结构和至少一组明确企业归属；流程图、架构图、技术路线和展商目录未误收。
- 全文和全部分页已扫描；同一底层文档只形成一个来源组。
- 来源图表清单、节点清单和企业清单已完成。
- 每个可读节点都有完整路径；每个企业只挂在直接证据支持的节点。
- 宽来源的范围变化已说明，没有只按关键词删除企业。
- 来源组一次性通过 CLI 写入，九字段、备注、URL、顺序和原子性约束满足。
- 所有写入、修改和终态操作使用有效 claim_token。
- 连续两轮没有新增独立合格来源后才提交主题终态。

# 产业链来源检索与解析

## 任务目标

按 Runner 中的正式主题寻找独立、高质量、全国范围的产业链来源，忠实还原来源实际表达的节点结构和企业归属，并通过 `industry-chain` CLI 写入固定九字段数据。

本任务不是总结行业知识，也不是建立“更合理”的标准产业链。模型上下文只作为**当前来源的临时工作区**；已经完成的来源以 Runner 中的持久化结果为准。

## 必需输入与能力

运行前必须具备：

- Runner 中的正式主题、`path`、`aliases` 和 `node_id`；
- 互联网搜索能力；
- 网页和 PDF 浏览、翻页、缩放或高分辨率渲染能力；
- 实际视觉读图能力；
- 可调用的 `industry-chain` CLI。

如果任务尚未创建 Runner，主题输入有两种方式：批量任务使用 `--config <topic_identity.yaml>`；用户只给一个正式主题时直接使用 `--topic <主题>` 创建单主题 Runner，不得为了单主题临时生成配置文件。

**新任务默认必须新建 Runner。** 除非用户明确要求继续、续跑或补跑某个已有 Runner，或明确提供 `runner_id`，否则不得扫描 `runs/` 寻找同主题历史结果，不得复用已有 JSON、XLSX、来源组或历史搜索结果，也不得据此跳过当前搜索流程。“再跑一次、重新跑、用最新版 Skill 跑”仍按新任务处理。续跑时只能使用用户指定的 Runner，不自行选择其它同主题 Runner。

**执行 Client 时以当前仓库源码为 CLI 合同。** 研究 Agent 默认使用 `python skills/researching-industry-chains/run_cli.py ...` 调用当前 checkout 的 Client；PATH 中已安装的 `industry-chain` 只作为人工快捷入口，不作为能力判断依据。如果已安装命令的 `--help` 与当前 Skill 或源码不一致，不得因此认定功能缺失，也不得回退到临时 YAML、旧参数或其它业务流程，直接改用项目本地 launcher。本文后续示例仍以 `industry-chain` 简写同一套参数；只有项目本地 launcher 本身无法运行时，才视为 CLI 能力缺失。

缺少影响网页/PDF 查看、视觉判断或 CLI 写入的关键能力时，不得用 OCR、正文或常识猜测代替；领取主题后发现能力不可用，提交失败状态。

## 业务不变量

本任务始终遵守以下规则：

1. 一个网页、报告或 PDF 独立形成一个来源组，不跨底层文档拼接节点或企业。
2. 来源展示的每个可读节点都必须处理，包括父节点和无企业节点。
3. 来源发现的每个可读企业或企业组都必须处理：挂到直接证据支持的最小节点，或明确记为无法归属。
4. 不用行业常识补节点、改节点名称、重排来源结构或猜企业归属。
5. 一个来源解析完成后立即写入 Runner，不等待其它来源。
6. CSV/XLSX 是来源事实的投影，不是 Agent 对产业链的重新整理。

在以下时点重新检查这一节：领取新主题后、开始一个新来源前、准备生成 `records` 前、准备提交主题终态前。无需反复全文重读 Skill。

## 来源准入规则

候选来源只有依次通过以下门槛，才进入深度解析。

### 1. 地域范围

除非正式主题自身明确要求地方范围，否则默认只接受研究对象为**全国、中国整体或全国市场**的来源。

默认排除：

- 省、市、区县级产业链；
- 园区、开发区产业链；
- 地方产业集群、招商图谱、地方重点企业分布。

判断的是**来源研究对象**，不是发布机构所在地。深圳研究机构发布的《中国机器人产业链》可以保留；国家级机构发布的《北京市机器人产业链》仍应排除。

来源可以只覆盖正式主题产业链的一部分，但其研究对象仍必须是正式主题本身。不得因为正式主题出现在某个更大产业链的节点、产品、原料、应用或案例中，就把整个上位产业链作为该主题的来源。

### 2. 来源质量

优先顺序：

1. 政府部门和政府研究机构、全国性行业协会、证券公司研究所、权威科研机构和研究院；
2. 头部咨询机构、专业行业研究机构、正式行业白皮书、上市公司或产业龙头的正式产业研究材料；
3. `references/preferred-sources.md` 中人工维护的专业站点；
4. 专业产业数据库、专业财经媒体的深度原创研究、垂直行业媒体的原创深度内容、大学或实验室产业研究材料。

普通新闻、聚合、营销、自媒体和低专业度转载默认跳过，例如普通腾讯新闻/搜狐/网易/今日头条/百家号页面、个人博客、营销软文、新闻聚合页和只摘录研报结论的资讯页。

发现转载时先识别原始研究主体并尝试找到原始报告或原发布页：

- 找到原始来源：使用原始来源，不保留转载页；
- 原始来源不可访问，但转载页完整保留产业链证据：可以使用转载页；
- 转载内容残缺，无法完整还原节点或企业：排除。

**发布日期不是来源准入门槛。** 2024 年及以后来源只具有搜索和处理优先级；不得仅因来源早于 2024 年而排除。较早来源只要其它准入条件合格，仍正常解析和写入，并在首行备注“来源早于2024年”；日期无法确认时写“发布日期未识别”。已有更新来源也不能据此自动否定较早的独立合格来源。

### 3. 主题一致性

来源表达的产业链研究对象本身必须与 Runner 中的正式主题一致。

以下情况可以视为一致：

- 来源直接使用正式主题；
- 来源使用 Runner 中已经批准的 `aliases`；
- 来源自身明确说明另一个名称就是正式主题的直接同义表达。

不得依靠外部行业常识自行认定同义词。

以下情况不一致，直接排除：

- 正式主题只是更大产业链中的一个节点；
- 正式主题只是来源中的一个产品、原材料、应用领域或案例；
- 来源主体讨论的是上位行业，只是在正文或产业链图中出现正式主题。

主题不一致时，不进入完整扫描、来源清单、节点清单、企业清单和 records 生成。

示例：

- 正式主题为“锡膏”，来源明确写“焊锡膏也叫锡膏”，且产业链研究对象是“焊锡膏行业产业链” → 合格；
- 正式主题为“锡膏”，来源研究对象是“微电子焊接材料产业链”，图中“锡膏”与“焊锡丝、焊锡条、助焊剂”等并列 → 不合格。

### 4. 产业链资格

来源必须同时满足：

1. 图、表或正文明确表达产业角色之间的连续关系，例如原材料/零部件 → 制造/服务 → 集成/运营 → 应用/客户，能够回答“谁提供什么给谁”；
2. 至少一组企业能够通过同一来源内部证据直接对应一个已有节点。

标题含“产业链”“全链路”“生态图谱”，或图中存在方框、箭头，本身不能证明产业链资格。

以下内容单独出现时不合格：

- 工艺流程、业务流程、工作流和工作原理；
- 技术路线、系统架构和功能模块图；
- 产品结构、零部件清单和应用场景集合；
- 企业名单、相关标的表、排行榜、展商目录、区域热力图和没有产业角色关系的生态版图。

未通过任一来源准入门槛时立即跳过，不进入反复截图、读图和深度解析。

## 单个主题执行流程

### 1. 确认主题

领取结果中的正式主题、`path` 和 `aliases` 是主题身份依据。`path` 只用于理解目录位置，不作为产业链节点。

搜索词覆盖正式主题、批准别名和必要的相关表达，可组合“产业链、产业图谱、全景图、研究报告、行业研究、企业布局、竞争格局”等限定词。

### 2. 搜索候选来源

搜索分两阶段执行。

#### 优质来源定向搜索

先读取 `references/preferred-sources.md`，围绕正式主题对人工维护的优先站点做少量定向搜索。

优先尝试：

```text
正式主题 + 产业链
正式主题 + 产业图谱
正式主题 + 行业研究
正式主题 + 研究报告
```

搜索工具支持站点限定时，优先使用域名限定，例如主题为“锡膏”时：

```text
site:askci.com 锡膏 产业链
site:qianzhan.com 锡膏 产业链
site:huaon.com 锡膏 产业链
site:chinabaogao.com 锡膏 产业链
site:chyxx.com 锡膏 产业链
site:eastmoney.com 锡膏 产业链
```

优先来源只是搜索入口，不是白名单。候选仍必须通过地域范围、主题一致性、产业链资格和企业证据规则。

不得把定向搜索扩成大量网站 × 大量关键词的笛卡尔积。每个优先站点只做少量与正式主题直接相关的检索。

Agent 不自动修改 `references/preferred-sources.md`。可以在任务汇报中指出值得人工加入优先来源库的新站点。

#### 开放网络搜索

完成优质来源定向搜索后，再使用 Agent 原生搜索能力扩大范围，发现种子库没有覆盖的高质量来源。

开放搜索先建立当前主题的**搜索表达集合**：

- Runner 正式主题始终保留，已批准 `aliases` 也可以用于搜索；
- 可以从搜索结果标题、摘要或当前候选来源自身的明确用词中补充最多 2 个**搜索用字面变体**；
- 搜索用字面变体只用于发现候选，不写入 Runner `aliases`，也不能作为主题一致性的证明；
- 没有可靠变体时只使用正式主题和已有 `aliases`，不为了凑数量自行生成大量近义词。

搜索阶段使用某个表达，不代表该表达已经通过主题一致性门禁。候选仍必须由正式主题、已批准 `aliases`，或来源自身明确同义说明来证明主题一致。

开放搜索按**搜索意图覆盖**执行，而不是按“随便换几组关键词”计轮次：

1. **结构发现**：搜索表达集合中的每个表达都必须至少执行一次 `表达 + 产业链`；必要时补 `表达 + 产业链结构` 或 `表达 + 产业链全景图`；
2. **视觉 / 引用发现**：使用 `表达 + 产业链 + 资料来源`，或 `表达 + 产业链图 / 全景图`；
3. **专业来源补漏**：使用 `表达 + 研究报告`，或 `表达 + PDF`。

`企业、竞争格局、行业研究` 等更宽查询只在前述搜索仍缺候选时补充，不要求对每个表达全部执行。不得把这些意图扩成“所有表达 × 所有关键词”的笛卡尔积；每次查询都应补一个尚未覆盖的搜索意图。

搜索结果或候选页面出现以下高价值线索时，优先做**有限引用追源**：

- 明确产业链图题；
- 明确报告标题；
- `资料来源：XX`；
- 明确原始研究机构；
- 转载页明确指出原始报告或作者。

追源查询优先使用高信息量组合，例如 `"产业链图题或报告标题" + 原始机构`，或 `原始机构 + 当前主题表达 + 产业链`。追源只处理当前明确线索：找到原始发布页、确认原始内容不可访问但当前转载完整可用，或该线索已经无法继续核验时立即停止；不得沿普通相关新闻、企业名称或无关链接无限扩散。追源得到的页面仍按正常来源准入规则判断。

搜索阶段可以一次发现多个候选 URL，但只做候选发现和快速筛选，不把多个来源同时放入深度解析上下文。

#### 网页候选快速侦察

搜索摘要只用于粗筛。候选网页在判断主题一致性、产业链资格和是否存在关键图表前，应实际打开页面。

网页判断同时使用两类信息：

- DOM / 正文：快速定位标题、正文小节、图题、表题、发布日期和“产业链、全景图、产业图谱、企业”等关键词；
- 浏览器实际渲染：确认页面真实显示的图片、表格、图表、框、箭头、分组和企业 Logo。

两者是协同关系，不得把“DOM / 正文没有抽取到图片”当成“页面没有图片”。

如果页面出现“产业链图、产业链全景图、产业链结构图、产业图谱、企业图、资料来源”等明显图题或视觉线索，必须使用 Agent 框架自带浏览器滚动到对应位置实际查看渲染内容，再判断是否合格。

候选阶段只做快速侦察：打开页面、定位相关区域、快速滚动并确认是否存在关键视觉证据。不要在尚未确认来源合格时进行重复截图、OCR、下载原图或精细裁切。

候选判断顺序固定为：

```text
搜索结果
→ 搜索摘要粗筛
→ 打开候选网页
→ DOM / 正文定位 + 浏览器视觉快速侦察
→ 全国范围
→ 来源专业性 / 原始来源优先
→ 主题一致性
→ 产业链资格
→ 单来源深度解析
```

明显不合格时立即跳过。

**禁止先打开很多文章全部读完，再统一解析和写入。**

### 3. 一次只处理一个来源

任何时候只允许存在一个“已经开始深度解析但尚未写入 Runner”的来源。

一旦开始完整阅读某个来源，在该来源完成解析、覆盖检查并成功写入 Runner 前，不得开始第二个来源的深度解析。

单来源事务固定按以下顺序执行：

```text
完整扫描来源
→ 来源清单
→ 节点清单
→ 企业清单
→ 还原节点树和企业归属
→ 生成九字段 records
→ 节点覆盖检查
→ 企业覆盖检查
→ 立即 dataset insert
→ 确认写入成功
→ 当前来源事务结束
```

### 4. 完整扫描当前来源

同一底层文档的正文、网页分页、主产业链图、补充节点图、后续企业图表和明确正文可以综合；其他 URL 或其他报告的内容不得补入。

网页出现页码、`下一页` 或类似分页入口时，确认总页数并扫描到最后一页。长篇 PDF 可以用目录、图表目录和文本搜索定位候选页，但用于节点或企业判断的图片页必须实际查看。

网页来源进入深度解析后，继续同步使用页面元素与实际渲染结果：

- DOM / 正文用于定位内容位置、读取可直接提取的文字、识别分页和图表标题；
- 浏览器视觉用于确认页面实际显示的图表，以及图片内部的节点层级、连接、分组和企业空间归属。

页面元素无法暴露某张图的图片节点、URL 或替代文本时，不得据此跳过该图；只要浏览器渲染结果中可见，就按视觉证据处理。

在当前上下文维护一份简短的**来源清单**，逐项登记：

- 页码、分页或图表位置；
- 类型：主产业链图、补充节点图、企业图表、明确正文、排除项；
- 是否已查看；
- 是否提供节点；
- 是否提供企业关系。

对实际用于还原产业链结构的主产业链图，同时记录可供人回看的位置说明，供来源组首行 `备注` 使用。

来源清单只回答“当前来源是否已经读完”，不写入 Runner。

### 5. 视觉读取：清楚即停止

先看完整页面或完整图。

快速侦察已经确认页面存在关键图表时，深度解析必须实际查看该图表；不得因为 DOM / 正文没有暴露图片节点而退回正文并把页面当作“无图”。

如果已经能够可靠读取节点文字、层级/连接关系、企业名称以及企业与节点的直接关系，立即进入解析，不再为了“更保险”重复截图、重复放大、OCR、下载原图或再次验证同一区域。

只有存在具体不可读内容时，才处理对应局部，例如：

- 某个节点文字看不清；
- 某条连接关系不清；
- 某组企业名过小；
- 表头和企业的对应关系不清。

此时只对必要局部裁切、放大或高分辨率渲染。OCR 只能辅助识字，不能替代视觉结构判断。

原则：

```text
清楚 → 解析
不清楚 → 只处理不清楚的局部
```

主产业链图整体无法可靠读取，且正文不能独立、明确地给出完整产业链结构和企业关系时，排除该来源，不提交残缺主图。

### 6. 建立节点清单

来源扫描结束后，先在当前上下文列出所有可读节点的完整路径，再生成 `records`。

例如：

```text
上游
上游 > 核心零部件
上游 > 核心零部件 > 丝杠
上游 > 核心零部件 > 减速器
```

每个节点只有“已投影”或“尚未投影”两种状态。存在尚未投影节点时，不得写入来源组。

还原节点时：

**当产业链图已经提供明确节点与层级时，以图作为结构骨架。正文可以补充图外但归属明确的节点和企业证据，但不得改写图中节点名称、改变图中已有父子关系、在图中已有层级之间插入正文推导出的中间层，也不得把视觉结构和正文结构重新融合成来源未直接展示的第三套结构。若图与正文存在名称或层级冲突，以图片/表格为准。**

- 以来源中的框、分组标题、连接线、缩进、包含关系和阅读方向为准；
- 图片或表格优先，正文中“包括、分为、由……构成”等明确枚举可补充结构；
- 父节点本身也是节点，无论是否有企业都保留；
- 子节点不能用父节点替代，并列节点分别成行；
- 无企业节点仍保留，公司留空；
- 一个框表达组合节点时原样保留；表达多个并列节点时拆开；
- 省略号、示意占位符和装饰文字不生成节点；
- 节点名称、层级和顺序保持来源原义，不标准化、不润色、不补全。

分类 1 至分类 4 必须连续；超过四级时，从第四级开始按原始顺序合并为 `第四级 > 第五级 > 第六级`，并在来源首行备注说明。

### 7. 建立企业清单并挂载企业

对当前来源中每个可读企业或企业组，在上下文中记录：

- 企业或企业组原文；
- 直接证据对应的节点；
- 状态：`已挂载` 或 `无法归属`。

不存在“读到了但没处理”的第三种状态。

企业归属证据按以下顺序判断：

1. 产业链图中的位置、连接、框或图例；
2. 企业表的标题、分组和字段；
3. 正文明示某企业生产、提供、运营或布局某个节点对应的产品或服务。

使用离企业名单最近的明确节点标题、表头或语义分组作为归属锚点。分号、分组标题或表格行已经区分企业组时，不得把相邻企业组合并到更宽的父节点。

“主要上市公司、相关企业、代表公司、相关标的”等名单不能仅凭主题相关性挂载；只有同一来源另有明确节点关系时才使用。

企业只写在直接证据支持的最小节点行：

- 证据只到父节点时只挂父节点，不向子节点继承；
- 同一路径企业合并到一行，完全重复名称删除；
- 按来源出现顺序用顿号连接；
- 证据冲突时依次采用图中明确位置、分组表/企业列表、正文明确介绍；
- 无法消解时不强行挂载；
- 优先使用来源内部确认的企业全称，只能确认品牌或简称时保留原样；
- 不用外部知识扩展、改写或推断。

公司字段只填写来源能够确认的企业实体名称。正文中的“旗下的、所属、由……控股、代表企业为”等关系描述只用于判断企业归属，不写入公司名称。例如来源写“有研粉材旗下的康普锡威”时，若实体名称可以明确识别，则公司填写 `康普锡威`，不填写 `有研粉材旗下的康普锡威`。不调用外部知识补全企业工商全称。

无法确认归属的企业不写入公司字段，并在来源首行备注中写明“发现但无法归属：企业名称”。

### 8. 生成九字段 records

只在当前来源完成节点清单和企业清单后生成固定九字段，不增加证据、置信度、搜索过程、截图或推理字段：

```json
{"records":[{
  "主题":"正式主题",
  "信源主体":"发布主体",
  "分类1":"上游",
  "分类2":"节点",
  "分类3":"",
  "分类4":"",
  "公司":"甲公司、乙公司",
  "信源URL":"https://example.com/report",
  "备注":"产业链图位置：第 12 页，图 3《XX产业链》"
}]}
```

一行表示“从根节点到当前节点的完整路径”以及直接归属于路径终点的企业集合，不是一家企业一行，也不能把整棵产业链压成一行。

九个字段全部是字符串。主题、信源主体、分类 1 和信源 URL 不能为空；分类不能断层；组内主题、信源主体和 URL 必须一致；只有第一行填写备注；来源组至少一行公司非空；信源 URL 必须是合法 HTTP(S) 地址。

来源组第一行 `备注` 必须包含**产业链图位置说明**，让人工可以回到原来源快速找到用于还原结构的产业链图：

- PDF / 报告：优先写页码，并补充图号或图题，例如 `产业链图位置：第 12 页，图 3《XX产业链》`；
- 网页：写可稳定定位的正文小节、图题或图片顺序，例如 `产业链图位置：正文“产业链结构”小节，第 2 张图《XX产业链》`；
- 使用多张产业链图共同还原结构时，把实际使用的图位置全部列出；
- 对网页来源，只有使用浏览器实际查看相关页面区域并确认不存在产业链图后，才允许填写 `产业链图位置：无`。页面出现产业链图题、图注或“资料来源”等明显线索时，不得仅依据正文抽取结果填写“无”；
- 合格来源确认没有产业链图，而是由表格或明确正文直接给出产业链结构时，不编造图片位置，写 `产业链图位置：无（结构来源：表格/正文，位置：具体页码或小节）`。

其它备注信息继续写在同一首行备注中，与产业链图位置用 `；` 分隔，例如发布日期、层级合并和无法归属企业。

来源组按原图或原文阅读顺序排列，父节点行放在其子节点之前。

信源主体按发布关系填写：

- 原始发布：`原始主体`；
- 转载或托管且原始主体明确：`发布平台（原始主体）`；
- 只能识别发布平台：`发布平台（原始主体未明）`。

如果已经找到可直接使用的原始发布页，则使用原始页和原始主体，不再提交转载页。

### 9. 完成前覆盖检查

写入前只做当前来源的完整性检查，不重新寻找其它文章验证本来源。

**节点覆盖：**

```text
来源节点 - 已投影节点 = ∅
```

节点清单中的每个可读节点都必须能在 `records` 中找到对应完整路径。

**企业覆盖：**

```text
来源企业 -（已挂载企业 + 无法归属企业）= ∅
```

以下任一情况都表示当前来源尚未完成：

- 读到企业，但既没有进入公司字段，也没有记为无法归属；
- 只解析主图企业，忽略同一来源后续企业图表；
- 因企业数量多而抽样、概括或用“等”代替明确可读名单；
- 只保留与搜索关键词最接近的一部分企业；
- 父节点或无企业节点被省略；
- 并列节点被合并；
- 父节点企业被继承给子节点。

覆盖未完成时继续处理当前来源，不打开下一篇来源，不调用 `dataset insert`。

### 10. 立即写入当前来源

当前来源同时通过节点覆盖和企业覆盖后，立即一次性写入：

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$env:PYTHONIOENCODING = 'utf-8'
$payload = @'
{"records":[{"主题":"正式主题","信源主体":"发布主体","分类1":"上游","分类2":"节点","分类3":"","分类4":"","公司":"企业名称","信源URL":"https://example.com/report","备注":"产业链图位置：第 12 页，图 3《XX产业链》"}]}
'@
$payload | industry-chain dataset insert --runner-id <runner_id> --scope source_group --parent-id <node_id> --claim-token <claim_token> --input -
```

**写入成功是当前来源事务的结束门槛。**

禁止：

```text
来源 A 解析完
来源 B 解析完
来源 C 解析完
最后统一写入
```

必须：

```text
A → insert 成功
B → insert 成功
C → insert 成功
```

如果 Client 返回：

- `SOURCE_GROUP_DUPLICATE_URL`；
- `SOURCE_GROUP_DUPLICATE_CONTENT`；

则当前候选视为“本 Runner 当前主题中已经存在的重复来源”：

1. 不修改节点、企业、URL 或备注来绕过去重；
2. 不拆成逐行写入；
3. 不重复提交；
4. 结束当前来源事务，继续下一个候选来源；
5. 该重复来源不计为“新增独立合格来源”。

写入成功后，后续工作以 Runner 中已持久化的数据为准。当前来源的来源清单、节点清单、企业清单和详细内容不再作为后续来源的工作上下文，只保留必要的来源去重信息和主题进度。

需要纠正已写入数据时，先用 `dataset get` 查看，再用 `dataset patch`、`dataset replace` 或 `dataset remove` 精确修改。XLSX 是交付投影，Runner JSON 是事实源。

### 11. 继续搜索与主题终态

每写入一个来源后再继续搜索或处理下一个候选来源，不设置固定来源数量。

**搜索饱和不按固定轮次数判断。** 准备结束搜索前必须确认：

1. 优质来源定向搜索已经执行；
2. 当前搜索表达集合中的每个表达都已经至少执行一次 `表达 + 产业链`；
3. 视觉 / 引用发现搜索已经覆盖；
4. 专业来源补漏搜索已经覆盖；
5. 当前发现的高价值图题、报告名、原始机构和转载追源线索都已处理；
6. 当前候选队列中没有尚未判断的潜在合格来源。

搜索用字面变体不是必需输入。如果搜索过程中没有发现可靠变体，不要求 Agent 凭常识创造变体，也不因此阻止搜索饱和。

满足以上覆盖后，如果完成尚缺的搜索意图仍没有产生新的独立候选，才算搜索饱和。重复来源错误不算新增来源。

准备提交终态前重新检查“业务不变量”，然后：

```text
industry-chain topic finish --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token> --outcome completed
industry-chain topic finish --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token> --outcome no_qualified_source
industry-chain topic fail --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token> --code <错误代码> --message <简短说明>
```

`completed` 要求至少一个来源组；`no_qualified_source` 要求没有来源组。浏览器、网络、视觉能力或运行环境出现系统性异常时提交失败，不把异常主题视为完成。

## 最小示例

### 父节点和并列子节点

来源：

```text
核心零部件
├─ 丝杠
├─ 减速器
└─ 传感器
```

必须保留四条路径：

```text
核心零部件
核心零部件 > 丝杠
核心零部件 > 减速器
核心零部件 > 传感器
```

### 企业证据只到父节点

来源：

```text
核心零部件：甲公司、乙公司
├─ 丝杠
└─ 减速器
```

正确投影：

```text
核心零部件          公司=甲公司、乙公司
核心零部件 > 丝杠   公司=
核心零部件 > 减速器 公司=
```

不得把甲公司、乙公司复制或猜分到子节点。

## Runner 与租约

创建 Runner 时，主题输入必须二选一：

```text
# 批量主题
industry-chain runner create --name <任务名称> --config <topic_identity.yaml路径>

# 单个主题
industry-chain runner create --name <任务名称> --topic <正式主题>
```

用户只给单个主题且没有 config 时，直接使用 `--topic`。不得为了兼容批量入口临时生成 YAML。单主题 Runner 只有 `node_0001`，`path` 为 `[正式主题]`，`aliases` 为空；创建后与批量 Runner 使用完全相同的 claim、insert、finish 流程。

后续 Runner 和主题命令显式传入 `--runner-id`：

```text
industry-chain runner status --runner-id <runner_id>
industry-chain topic claim-next --runner-id <runner_id>
industry-chain topic claim --runner-id <runner_id> --node-id <node_id>
industry-chain topic claim --runner-id <runner_id> --node-id <node_id> --reopen
```

保存领取响应中的 `claim_token` 和 `lease_expires_at`。主题处于 `in_progress` 时，数据写入、修改、替换、删除、续租、完成和失败都携带当前有效令牌。

长时间处理至少每 20 分钟续租一次：

```text
industry-chain topic renew --runner-id <runner_id> --node-id <node_id> --claim-token <claim_token>
```

不要创建中间 JSON；截图、PDF、网页下载物、OCR 文件和日志只用于当前判断，不写入 Runner。Runner 目录只保留 `runner.json` 和交付 XLSX。

## SubAgent 派发模板

每个 SubAgent 只处理互不重叠的 `node_id` 范围，不预设来源、节点或企业：

```text
你负责 Runner {{runner_id}} 的 node_id {{node_id 或范围}}。先阅读 skills/researching-industry-chains/SKILL.md，领取或确认主题并保存有效 claim_token。

严格按 Skill 执行：先做优质来源定向搜索，再按结构发现、视觉 / 引用发现、专业来源补漏覆盖开放搜索；搜索结果出现图题、报告名或原始研究主体时做有限追源，搜索用字面变体只帮助发现候选，不放宽主题一致性；网页候选先用 DOM / 正文定位，再用 Agent 自带浏览器快速查看实际渲染内容；候选必须依次通过全国范围、专业性、原始来源优先、主题一致性和产业链资格；一次只深度处理一个来源；图片已经清楚时停止额外验证；当前来源完整还原节点和企业、通过覆盖检查后立即通过 industry-chain CLI 写入，再处理下一来源。

如果 Client 返回 SOURCE_GROUP_DUPLICATE_URL 或 SOURCE_GROUP_DUPLICATE_CONTENT，直接跳过该重复候选，不修改 records 绕过去重。

所有数据操作和终态操作携带有效 claim_token。搜索饱和后提交 completed、no_qualified_source 或 fail，并汇报 node_id、正式主题、终态、来源组数、数据行数、来源 URL 和交付 XLSX 路径。
```

主题终态后汇报 `node_id`、正式主题、终态、来源组数量、数据行数、来源 URL 和交付 XLSX 路径；失败时补充原因。
